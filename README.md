# Web QA Automation - Cypress Overview
 Automated E2E test project created with Cypress for DemoQA, as part of web QA Engineer position process.
 This project focuses on representative user interactions and important scenarios, including positive and negative flows, validation scenarios and test evidence generation

## Application Under Test
DemoQA

Base URL:

https://demoqa.com

## Tech Stack
- Cypress 16
- JavaScript
- Node.js
- Page Object Model
- Cypress Fixtures
- cypress-mochawesome-reporter
- cypress-real-events
- Google Chrome
- macOS

## Folder responsibilities
- e2e/ - Cypress test specifications organized by application area
- pages/ - Page objects containing selectors and reusable page interactions
- fixtures/ - Test data used by automated scenarios
- test-files/ - Files used during tests, such as images for upload scenarios
- utils/ - Reusable data formatting and helper logic
- support/ - Global Cypress configuration and shared test behavior

## Prerequisites
Before running the project, make sure you have the following tools installed in your machine:

- Node.js 22 (or above)
- npm
- Google Chrome
- git

## Installation

- Clone the repository

https://github.com/samara-c/web-qa-cypress 

- Enter the project directory "web-qa-cypress"
- Install project dependencies using 

```npm install```

## Running the tests
Run the complete test suite using

```npm test ```

Test suite is configures to use Google Chrome as default browser

### Headed execution
To execute the tests while displaying the browser:

```npx cypress run --headed --browser chrome```

### Cypress interactive mode
To open Cypress test runner:

```npx cypress open```

Select:
- E2E Testing
- Google Chrome
- The spec you want to execute

### Running a specific spec
To run a specific spec, for example forms page:

```npx cypress run --browser chrome --spec "cypress/e2e/forms/practice-form.cy.js"```

## Test Reports
The project uses cypress-mochawesome-reporter to generate HTML test execution reports.

Reports include:
- Test suite results
- Passed and failed tests
- Execution duration
- Charts
- Screenshots
- Failure information

A new report is generated after test execution
Report files use the execution status and timestamp in their names to prevent previous reports from being overwritten and can be found under cypress/reports/

### Screenshots
Screenshots are captured after each test execution and are also automatically generated by Cypress when a test fails. They can be found under cypress/screenshots/

## Test Design
The project follows a Page Object Model approach
Test responsibilities are separated as follows:
- Specs define scenarios and assertions.
- Page Objects contain selectors and page interactions.
- Fixtures contain reusable test data.
- Utilities handle reusable data transformations

Selectors prioritize stable attributes and fixed waits are avoided.

## Test Data
Test data for the Practice Form is stored in

```cypress/fixtures/practice-form-data.json```

Valid and invalid values are separated to avoid unnecessary duplication between scenarios
